## 从已接受结果提炼的工作流补充

### Nuke多窗口本地登记发现与切换真实身份核验
适用条件：同一工作站运行多个 Nuke 实例，通过统一 MCP 列出并安全切换目标工程时。

每个 Nuke 实例绑定独占端口并原子发布含 PID、端口、随机会话 ID 和工程路径的心跳登记；列出会话时只读登记快照，不主动探测占用命令通道。切换目标时重新校验握手 PID、会话 ID 与 get_script_info 路径；新目标核验通过前保留原健康连接，将切换与工具派发放在同一串行锁内，连接超时立即断开并丢弃旧队列。

原因与注意：防止多窗口并发切换时把节点操作误发到另一个打开的镜头工程。

### Windows Nuke多实例固定端口冲突排查（独占绑定与真实PID核验）
适用条件：Windows 同时打开多个 Nuke 窗口，桥接报 Running 但连错镜头或连接失败时。

不要只看菜单栏的 Running 提示，先比对实际监听端口的 PID 与目标 Nuke 窗口工程路径。端口冲突时停止非目标实例桥接并重启目标实例，通过握手 PID 与 get_script_info 绝对路径双重确认。Windows 侧桥接 socket 应使用 SO_EXCLUSIVEADDRUSE 并在绑定失败时清理 socket，让冲突实例明确报错，禁止静默改端口或猜测目标。

原因与注意：Windows 下 SO_REUSEADDR 允许多个 Nuke 进程绑定同一端口，极易导致命令静默发往错误工程。

### 工程保留用户主版本号，追加两位助手迭代序号
适用条件：助手修改并另存 Nuke 工程脚本（.nk）时。

保留用户原有主版本号及扩展名，不擅自升主版本号；在原版本段后追加两位助手迭代序号：例如 v02.nk → v02_01.nk → v02_02.nk。不叠加多层序号，不覆盖已有迭代，也不为规范而擅自重命名未修改的工程。

原因与注意：与用户的版本流转习惯保持一致，便于清晰区分用户正式版与助手迭代稿。
