# 单机模式与共享数据服务

本地插件与服务端分别部署。单机模式继续使用 SQLite；可选的数据服务模式通过 HTTPS、IP、端口和 API Key 访问独立服务，共用经验、规范、模板与案例。

服务端源码、依赖、Dockerfile 和 Compose 位于 [services/data-service](../services/data-service/README.md)，不启动本地 MCP 或 DCC。Docker 直接连接已有 MySQL 5.7+，不创建数据库容器。

## 本地单机模式

```powershell
$env:FX_AGENT_DATA_MODE = 'local'
$env:FX_AGENT_DATA_ROOT = 'D:\FX-Agent\data'
```

即使保留服务配置文件，显式 local 模式也不连接服务。

## 数据服务模式

```powershell
$env:FX_AGENT_DATA_MODE = 'service'
$env:FX_AGENT_SERVER_IP = '118.24.73.40'
$env:FX_AGENT_SERVER_PORT = '18443'
$env:FX_AGENT_API_KEY = '<从管理员获得的API Key>'
$env:FX_AGENT_CA_FILE = 'C:\FX-Agent\server.crt'
```

CA_FILE 用于信任自建服务的专用证书；使用系统已信任的正式证书时可以省略。不要禁用证书校验。持久化变量后需重启 Codex、相关 DCC 和旧启动器。

也可将 server_ip、port、api_key、ca_file 保存到用户私密 JSON 文件，再设置 FX_AGENT_CLIENT_CONFIG 指向它。配置文件优先于旧的 SERVICE_URL/TOKEN 变量。fx_get_data_service_status 可核对当前模式和连接。

同一 API Key 可供多设备共用。设备 ID 用来区分任务与进度，只是团队内的逻辑命名空间，不是持 Key 用户之间的安全隔离；需要独立撤销时使用不同 Key。

服务模式默认上传当前工程、输入文件与归档证据，单文件上限 512 MiB；归档或完成任务时拒绝使用已经在本机删除的旧证据。目录模板应先上传到服务端的明确输入目录。原知识目录 ZIP 由部署管理员一次性上传关联。

API Key 只在创建时显示完整值，服务端仅保存哈希。管理员密码与数据 Key 分离；共享 Key 不提供网页管理权限。

## 其他设备更新

开发期间从 `dev` 分支更新；改动须先在开发设备提交并推送，其他设备才能拉取。保留设备上已有的本地修改，再执行：

```powershell
git switch dev
git pull --ff-only origin dev
.\Install-FX-Agent.bat -Components Both
```

按实际使用的软件选择 `Houdini`、`Nuke`、`Maya`、`Both`（Houdini 与 Nuke）或 `All`。更新前关闭相关 DCC 及其桥接进程，安装器会同步依赖、更新桥接与 MCP 注册，并保留无关配置。完成后重新打开软件并重启 Codex。

本次更新必须重新运行安装器，因为 Codex 的 MCP 子进程需要显式 `env_vars` 白名单才能读取知识服务变量。三个入口都会登记变量名，不把 API Key 明文写进仓库。其他设备还需自行配置 IP、端口、Key、CA_FILE，并将证书保存到该设备对应路径；环境变量不会随 Git 同步。

后续仅业务代码变动、依赖和安装配置均未变化时，源码安装可拉取后重启；依赖变化仍需同步依赖，桥接或注册变化仍需重新安装。客户端更新不会更新云端容器，服务端变动需单独重新构建和部署。重启后调用 `fx_get_data_service_status`，应返回 `mode: shared`，再验证知识读取。
