# 效果识别与二次学习

工程结构归档与效果理解分开验收。源工程、旧快照、旧效果卡均保留；新理解追加修订。画面由当前宿主助手实际查看，服务不运行另一个模型，也不会通过解析节点名自动判断画面。

## 学习入口

1. 原 `fx_plan_template_import` 同时列出视频数量与序列线索；选择版本后按原流程归档工程。
2. 调用 `fx_plan_effect_study(study_id, media_source=用户提供目录)`。按 `section`（annotations/render_outputs/media）、`offset`、`limit` 分页；每个集合有独立的 `next_offsets`。`detail_required` 时增加预算，不把空页当作没有资料。
3. 先看网络框标题、便签和注释，再读节点。比如作者写“能量”，保留主题原文；框的几何范围只生成候选成员，不能冒充显式成员关系。
4. GEO 分支不清楚时填写 `node_path`，看 `focus_render_node_paths`，追踪输出选择、容器内部节点、连线和静态对象引用。无法求值的表达式、缓存桥接、Take与运行时可见性仍需宿主核对，不能声称静态追踪一定穷尽全部渲染关系。
5. 视频查看完整运动过程；序列查看首尾、关键阶段与连续变化。建议采样最多九帧，只是开始查看的入口。内部缺帧和可解析的渲染预期帧段缺帧分开报告。未解析的步长/表达式显式标记。
6. 路径相符仅为候选关联，所有素材初始都是 `not_viewed`。同目录视频不盲目关联全部工程；路径搬迁或版本不一致时核对，必要时询问用户。

`media_source` 必须是用户提供的范围；不会因工程里出现绝对路径而遍历外部目录。计划不解码媒体、不模拟、不渲染、不改当前GUI工程。宿主使用可用解码工具/软件实际查看，打不开时记录具体问题。

## 效果卡字段

| 字段 | 用途 |
| --- | --- |
| title / effect_kind | 可理解的效果名及具体表现，如环境烟、爆炸烟、能量粒子 |
| effect_family | 大类，例如粒子、烟雾、火焰，可组合 |
| behaviors | 已有依据的运动，如环绕、吸引、消散；静态表现可明确写静止 |
| naming_basis / author_labels | 命名来源与作者标注原文；provisional表示暂定 |
| questions | 工程内查证后仍需问用户的具体问题 |
| visual_evidence | 视频时间段或序列帧段、观察、渲染节点和已归档代表样本 |
| reuse_mode / reuse_node_paths / reuse_dependency_notes | 参考搭建、复制节点或混合复用，以及节点范围和依赖边界 |

作者标注需与快照中原文一致。`VisualEvidence.case_id` 可指向同项目的独立样本案例：用 `fx_archive_case` 归档新样本，再引用相对归档路径。无需为补证据重复归档原工程或复制全部序列。

旧卡保持可检索，标记 `needs_relearning`。有问题的卡为 `needs_confirmation`；结构化字段齐全但无足够来源的为 `needs_visual_evidence`。识别来源可为用户真实说明或宿主实际查看后的画面证据，不代表已经成功复现。

## 复核与疑问

`fx_review_template_effects` 除全部节点、当前卡ID及技术节点排除理由外，还需显式 `media_source` 与完整 `media_reviews`。

- viewed：填写实际观察及关联的当前卡ID。
- unavailable：说明读取问题及需要用户补充什么。
- unassigned：说明工程/版本/分支关联的歧义。
- excluded：仅用于明确无关的素材，例如贴图，并填写理由。

缺少条目的复核会拒绝；unavailable/unassigned会保存为待确认问题，阻止完成。卡片本身的未解问题或暂定身份也阻止完成。复核通过记录的是宿主已检查范围，不是服务自动证实视觉理解。源素材之后变化需要重新盘点复核，不靠旧记录担保新文件。

复核形成父子链，独立分支并存时要求重审；迁移和合并不依赖行号或设备时钟选择结果。

## 检索、复用和 Dream

`fx_search_effects("粒子环绕吸引")` 同时核对类别与运动。返回 `match_kind`、`missing_concepts`、`unverified_terms`，区分完整、部分和候选结果。它是本地加权文本与有限同义词/结构化概念匹配，不是通用视觉或向量语义理解。

选择卡后导出工作副本。复制节点时核对上下游、参数引用、动画、材质、插件和外部资源；只把准备复用的节点带入制作工程。此版本记录复制边界，实际节点复制仍由现有DCC工具执行，静态学习不会执行源工程。

`fx_get_effect_learning_queue` 提供当前工程的二次学习清单。`fx_refine_effect(card_id, updates, sources, reason)` 只补改变的字段，保留原方法和其他描述，创建同一变体的新修订；过期卡拒绝写入。不同效果变体仍单独建卡。

Dream预览保留候选及其祖先经验中的 `effect_card_ids`，并返回 `effect_learning` 后续工作要求。当前宿主在新证据使效果更明确时调用 `fx_refine_effect`，补效果名和其他信息；无新理解不制造修订。来源用 `dream:`、`memory:`、`feedback:`、`effect_card:` 的真实ID，保存原因和来源资料；旧卡不删除。Dream归纳不会自动把效果卡升级为用户认可或成功经验。
