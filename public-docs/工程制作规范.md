# 工程制作规范

> 由用户明确要求形成的制作约束。更新日期：2026-11-02。规则优先于历史经验、模板默认值和学习生成的步骤。后续用户明确修改要求时记录新修订，不能由推测或使用次数自行改写。

## 1. 文件读取

- Houdini 工程中的 File 节点、贴图、模型及其他外部资产读取均使用 `$HIP/` 工程相对路径。
- Houdini 实际变量写法是 `$HIP`，不是人民币符号 `￥HIP`。
- 例：`$HIP/assets/geo/rock.bgeo.sc`、`$HIP/assets/tex/rock.<UDIM>.exr`、`$HIP/reference/target.png`。
- 外部素材先复制到当前工程目录，再设置节点读取路径；不能只把绝对路径改写成一个实际上不存在的 `$HIP` 路径。
- 不使用盘符绝对路径、`$JOB`、父目录逃逸、未知环境变量或未核实的表达式替代该约定。
- `${HIP}/...` 与 `$HIP/...` 语义相同，检查器兼容前者；制作时统一优先使用 `$HIP/...`。

## 2. File Cache 输出

统一为：

```text
$HIP/geo/$OS/$OS.$F4.bgeo.sc
```

- `$OS` 为节点名，`$F4` 为四位帧号。
- 当前 Houdini 22 的 `filecache::2.0` 使用 File Path 的 Explicit 模式：`filemethod=explicit`，`file` 设置为上述字符串。
- 不直接覆盖内部派生参数 `sopoutput`。已有模板需要同时检查实际计算出的输出路径，不能只看 `file` 文本。
- 节点采用能区分制作模块的名字，避免不同网络的同名缓存落到同一位置。重命名节点会改变 `$OS`，已有缓存要检查后再复用。
- 缓存前先保存工作 HIP；同一文件路径不代表缓存内容仍与当前网络一致，记录缓存生成时的工程版本与制作设置。
- RBD、Vellum 等需要多个数据流时继续选择合适的 I/O 节点，不用只保留单输出的 File Cache 破坏约束或碰撞数据。其专用格式路径另外检查，不能硬套 bgeo.sc 丢失信息。

## 3. 工程、参考与案例

- 学习参考模板优先只读，试验使用副本；不修改唯一原件。
- 有工程支撑的经验需要归档工程副本、相关图片、必要依赖和文件清单。
- 工程节点保存 `$HIP` 相对路径；归档工具读取本机源文件时仍接受绝对路径。这是文件系统定位，不能反过来把绝对路径写进制作节点。
- 复制后检查真实文件与哈希；没有完成依赖、打开和画面检查时，不声明完整可复现。

## 4. 制作与确认

- Codex 负责分析、操作和效果判断；优先原生节点与批量工具，查真实参数与接口后再设置。
- 修改后检查网络和数据；到视觉阶段实际查看截图或预览，动态效果检查多个时间点。
- 草稿与正式制作分开；遵循已有缓存、渲染、进度和取消流程。
- 不移动既有节点、不自动排版，不通过任意 Python 绕开专用工具或路径检查。

## 5. 对话形成规范与经验

1. 用户表达长期要求：保存规则内容、用户原话、来源、适用范围和修订号。
2. 用户提出纠错：保存问题表现、修改思路、具体调整、实际结果以及相关工程与图片。
3. 用户确认最终效果：把实际采用的方案提炼成适用条件、步骤、关键参数和失败注意项；关联最终案例与纠错轨迹。
4. 下一次同类效果：先读取规范，再召回相关成功经验与历史失败原因，从已验证的方案起步，并验证对新镜头是否适用。
5. 记忆整理：合并重复检索信息、保留来源与纠正历史；推测不能因反复出现而升级成事实。当前用户明确要求优先于历史做法。

## 6. 自动检查的实际边界

当前新增服务桥接层覆盖常见文件参数的直接设置、批量建图、SOP 线性链、File/File Cache 创建与 File Cache 写入。Pyro/RBD/FLIP 原生模拟助手创建普通 File Cache 后，会在返回前设置显式规范路径并回读确认；专用 I/O 节点保留原有流语义。

上游 `import_file` 先按原字符串检查文件存在，且会把绝对路径写入节点，暂不能同时满足本规范。当前明确拒绝该快捷工具并指引使用 `build_network` 创建对应读取节点，不把只能通过前缀校验的半兼容实现当作可用能力。

这不是 Houdini 的全局沙箱。任意代码、回调、HDA 内部、自定义渲染器和手动 UI 都可能读写文件，不能声称仅凭这些前置检查已经审计整份工程。Codex 仍需按本规范检查模板和最终工程，未来补充完整文件参数扫描。

检查器对未知路径表达式采取拒绝策略，不会执行表达式来猜测其是否安全。它验证路径形式与覆盖范围内的实际输出，不证明资产存在、软链接未逃逸或整段缓存都已正确生成。

参考：[SideFX File Cache 文档](https://www.sidefx.com/docs/houdini/nodes/sop/filecache)。当前参数名称另经运行中 Houdini `22.0.466` 的节点卡片核实。
