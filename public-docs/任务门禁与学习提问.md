# 任务门禁与学习提问

门禁默认启用，统一作用于FX Agent的Houdini和Nuke MCP工具入口。由服务校验步骤与证据，宿主助手仍负责理解、方案选择、画面判断和向用户提问，不启动额外模型。

## 顺序与接口

1. 理解需求，明确目标、输入/参考、验收要求和预算；只读查看软件、实际工程、端口及模块目录。
2. `fx_begin_task(spec)` 创建任务，保存project_id、shot_id、software、kind（production/learning）、scene_path、endpoint、goal、acceptance、budget、modules和可选input_paths。
3. 规范、指南、模块补充、效果卡/经验检索和来源展开携带 `fx_task_id`。读取规范需带project_id，从offset=0按next_offset完整翻页，detail_required规则另行展开。Houdini还需discipline及对应模块原指南。
4. `fx_set_task_plan` 保存方法、适用条件、当前需求差异和实际展开过的selected_sources。引用采用effect_card:/memory:/template_study:ID。找不到适用方案时说明no_match_reason，不编造命中。
5. 节点修改、参数、保存、缓存、渲染以及学习写入工具带同一fx_task_id；服务在调用原函数前核对门禁并剥离任务参数，不向原软件传递额外参数。批量操作共享证据，无须每次重读知识。
6. 实际保存、结构检查、查看预览并归档后，`fx_finish_task` 验证完成条件。用户确认后，accepted反馈及fx_finalize_learning也必须携带该任务ID且归档/项目/镜头/软件一致。

`fx_get_task` 默认只返回状态、缺少的步骤和开放问题数量；需要问题/证据全文时才用detail=true。`fx_update_task` 使用当前revision和完整新spec更新，旧方案与读取凭据失效，需要重新核对后再放行。

## 什么会使凭据失效

- 需求或目标工程/端口更新：旧方案、保存与校验失效。
- 指定输入文件的大小/修改时间变化、用户规范修订变化：拒绝旧放行，要求更新任务并重新检查。
- 软件实际返回的帧率、帧段及Nuke格式/色彩管理变化：拒绝旧现场设置快照。
- 任一任务修改同一端口现场：该端口其他任务的旧保存与校验失效。
- 修改可能部分失败时，仍先使旧校验失效。保存或校验失败不得沿用之前的成功记录。确认提示不是实际保存。
- 开放问题或所读来源存在争议：要求查证/提问，不能按已解决方案完成或升级成功经验。

读取调查和取消操作始终可用。带任务ID的结构验证还需匹配任务现场，不能把另一工程的校验记入本任务。另存目标变化先更新任务，服务保留上一个scene_path以核对另存来源。重启/续作先核对现场并更新任务，不直接沿用旧验证结论。

## 控制上下文消耗

服务保存轻量读取回执，不向模型重复回传整套知识。任务不变时复用回执；selected_sources必须来自实际读过的完整卡片、经验或完整snapshot，不允许仅读截断内容或尾页就声称读过全文。

模块补充超过返回预算时，摘要只作索引。允许按module检索并完整展开所需经验/效果卡，在selected_sources引用与该模块相关的来源；该模块实际经验检索零命中时，可说明理由并依据已读原指南继续。这样不会因MD超过12,000字符上限而永久无法放行，也不要求整本模块进入上下文。规范全文/详情的连续覆盖仍必须满足。

## 学习提问

对效果含义、分支用途、输入、参数作用、版本与输出对应等不确定处，先查看现有工程、作者标注、上下游和可用媒体。仍不理解时：

1. 用 `fx_task_question` 保存具体问题、已查证情况和需要用户补充的内容。
2. 工具返回ask_user后，由宿主助手在当前对话集中发问；工具返回本身不等于问题已经送达用户。
3. 继续不受影响的只读调查或其他独立任务，不反复轮询等答复。
4. 用户回答后，用question_id、answer、真实user_quote与source_ref保存，必要时修订效果卡或更新任务范围。
5. 未解决问题不能通过finish；学习任务还需相关study的效果/素材复核完成。学习完成不升级为实际制作成功。

读取效果卡中已有questions或实际冲突全文时，会自动为任务保留问题，并返回task_action_required与问题ID。助手不能伪造用户答复，服务存储答复归因但无法独立认证聊天原话。

## 完成条件与边界

制作任务要求最后修改后的实际保存、同现场结构检查，以及匹配项目/镜头的当前工程和preview归档；工程副本SHA-256须与当前磁盘保存文件一致。Houdini使用verify_network，Nuke使用find_broken_reads；后者主要覆盖缺失Read检查，不能代替最终画面验证。verification_note必须是助手实际查看结果后的说明。

门禁保证本项目MCP入口的顺序、作用范围和记录条件，不是DCC全局沙箱。手动操作、直接连接底层桥接、其他插件以及脚本内部的任意行为不在同等保证范围内；视觉正确性和是否真正理解需求仍需实际判断。budget当前记录约束，并不提供自动计费或强行中止渲染的资源调度器。

任务保存在data/memory.sqlite3的task_gates表，SQLite schema=9；端口锁为data/task-locks中的临时OS锁，进程退出即释放。整体迁移可携带任务记录，跨设备导入不会把另一设备的运行任务作为本机放行状态。重新核对本机现场并更新任务后再操作。

更新后重启Codex以加载工具和skill；`fx_status.task_gate_version=1` 表示已加载门禁。
