# 工程模板学习、复用与迁移

FX Agent 可以只读导入单个 `.hip/.hiplc/.hipnc/.nk`，也可以盘点和学习混有 Houdini、Nuke、渲染序列、MOV、ABC 与缓存的目录。原工程、提取资料及经验统一保存在当前 `data_root`，默认本项目 `data/`。不启动第二套 MCP 桥接、模型或独立知识库。

## 使用方式

重启 Codex 后加载新增工具与 `fx-project-learn` 技能。本机原有独立 `fx-template-learn` 保留；新名称避免其默认 F 盘知识库与当前 data 混用。可直接说：

> 使用 FX Agent 学习 D:/FX/模板/卷浪。项目为模板库，镜头为 ocean001。先盘点，再只读学习 Houdini 和 Nuke 工程，不修改任何参数；只归档必要文件，序列和 ABC 不整批复制。分析制作方法，标明证据和未验证内容，保存候选经验。

实际流程：

1. `fx_plan_template_import`：只读盘点，不创建数据目录。列出工程、序列组、缓存数量及归档策略；跳过 backup、自动备份和目录链接。超出扫描数或工程数上限时要求缩小目录，不默默截掉工程。
2. 宿主助手先筛选 Houdini 工程：按镜头、相对目录和名称用途分别分组，同组优先版本号最高者（按数值比较，v10 高于 v02）；全部无版本号时选修改时间最新者，同版本号也以修改时间作次级比较。同镜头中名称区分的身体能量、地面烟雾等工程各自选最新，不能只留一个。混有版本号与无版本号时优先最高明确版本并报告无版本号文件；时间并列或分组不明确时列出歧义。报告选中与跳过的依据，再逐个将选中文件传给 `fx_learn_templates` 归档并静态提取；目录盘点和直接传目录的导入工具本身不自动筛选版本。默认不归档旧版；用户指定文件或要求历史版本比较时遵从用户要求。按单个工程隔离失败，重跑批次可以续学。明确的预览与附加资源通过 `files=[{path, role}]` 指定，只能附加到单工程，避免将同一成片盲目关联给整批工程。
3. `fx_get_template`：先读 summary，再按 `nodes/connections/patterns` 分页。`snapshot_text` 按字符读取原始快照 JSON；`history` 查看修订、同内容来源与分支。`dependencies/omitted_files/artifacts/parent_ids/limitations` 可分别分页。
4. 当前宿主助手分析节点、参数、曲线、VEX/脚本和流程；需要视觉结论时实际查看明确关联的预览。用 `fx_annotate_template_effects` 逐张标注实际效果，同方案的参数/动态/渲染变体分别保留，并用 `fx_review_template_effects` 记录检查范围。用 `fx_learn_template_experience` 保存候选解释。
5. 下次先 `fx_search_templates` 检索案例，再按现有工作流检索成功经验。需要原工程时用 `fx_export_template` 导出到全新工作目录。

按目标外观或动态找案例时优先使用 `fx_search_effects` 和 `fx_get_effect`，例如“角色身体能量粒子”，无需知道工程名。效果卡、共用方案、复核、基础规范快照及迁移说明见 [效果指示卡与基础规范](效果指示卡与基础规范.md)。

没有重启 MCP 时，也可用命令行：

```powershell
# 只盘点，不写 data
.venv\Scripts\python.exe scripts/learn_templates.py "D:/FX/模板/卷浪"

# 正式归档和提取，默认使用本项目 data
.venv\Scripts\python.exe scripts/learn_templates.py "D:/FX/模板/卷浪" --apply --project-id 模板库 --shot-id ocean001

# 单工程关联指定预览，并用稳定名称跟随工程搬迁/改名
.venv\Scripts\python.exe scripts/learn_templates.py "D:/FX/模板/卷浪/main.hiplc" --apply --project-id 模板库 --shot-id ocean001 --template-key ocean-wave-main --preview "D:/FX/模板/卷浪/final.mov" --module ocean
```

命令行可指定 `--data-root`、`--max-total-mib`、`--max-batch-mib`、`--max-asset-mib`。默认只盘点；实际导入要求项目和镜头。失败文件返回非零退出码；partial 会明确列出，不伪装为完整提取。

## 源文件只读

导入流程不调用 Houdini/Nuke，不打开或切换当前 GUI，不求值表达式，不执行回调、按钮、Python 或 Tcl，不 cook、保存、写缓存或渲染。节点布局、参数、脚本和曲线以文本提取；工程里的说明属于资料，不能作为代理指令。

复制时核对提取内容与归档副本 SHA-256，不一致则拒绝发布该次归档；原文件不恢复、不覆盖。已有有效修订继续保留。归档和知识写入 data，临时文件也位于 data 下。

### 提取内容和边界

- Houdini：复用固定版本的 kleer001 CPIO 解析器，并适配 SideFX 节间填充、UTF-8、绝对/相对连接、节点布局及多行参数。保存原始 `parm/chn/def/init/spare/net/inp` 等文本、便签、网络框与全局设置。
- Nuke：静态解析嵌套块、Group、push/set 栈和输入关系；保留 knob、曲线、回调、布局及脚本原文。布局命令和 add_layer 不当作节点，不执行 Tcl/Python。
- 提取整套场景、连接子图、去重节点配置，保存可搜索文本；检索采用本地 BM25，支持中英文。
- 不声称静态解析完全替代 HOM/Nuke API。未知/损坏/加密容器、未识别命令会记录 partial；原工程仍可保留。`.hiplc` 被纳入扫描不代表任意版本/许可变体都能静态解析。
- 原始曲线/表达式文本保留，不冒充已计算的关键帧值。外部 HDA/Gizmo 的内部网络、插件可用性、仿真结果和画面均未验证；缺缓存不阻断结构学习。

## 精简归档

| 项目 | 默认处理 |
| --- | --- |
| 原始 HIP/NK | 复制独立副本，保留校验值 |
| 提取 JSON、节点配置与索引 | 保存在 data 的案例及 SQLite 中 |
| 工程输入范围内能明确识别的 HDR、贴图等静态依赖 | 体积允许时复制；外部引用和不明确表达式保留说明 |
| MOV、参考图、代表性序列帧 | 显式指定，默认最多3份；不自动认定与工程版本对应 |
| ABC、USD、几何/模拟缓存 | 默认仅保留可识别引用及元数据，不复制内容 |
| 渲染序列、UDIM集合 | 默认不整批复制；需要的代表帧通过 preview 明确选择 |
| Nuke Write/DeepWrite 等输出 | 不作为必要输入自动归档 |
| backup、自动备份、目录链接 | 跳过 |

默认单工程归档副本上限256 MiB、整批512 MiB、单资源32 MiB，统计包含生成的 JSON。超过上限的资源记录遗漏原因；工程本体与必要元数据都放不下时，该工程失败。可显式调整 `TemplatePolicy`；缓存即使显式选择也默认不复制，只有明确设置 `archive_caches=true` 且符合体积限制时例外。

这些是归档副本预算，不是整个 data 的永久空间配额；历史修订和多次学习会继续积累。不同案例目前各有独立资源副本，批次预算限制总增量；没有宣称全库物理去重。重复导入同一未变工程不创建新案例。大缓存不计算全文件 SHA；可识别缓存的大小/时间只是元数据证据。

导出保持原参数/路径文本，尽量恢复工程目录内的相对布局。外部资源放在 `external/` 并保留映射；相同目标和相同内容只复制一次。生成资料使用独立 `.fx-template-<study_id>/` 目录，返回实际 manifest_path，避免覆盖原有同名附件。绝对路径、被省略的缓存/序列、外部插件需在工作副本中核对，不能称为完整可复现包。

## 数据组织与记忆迭代

```text
data/
  memory.sqlite3                 # template_studies、来源/修订、检索文本及原有记忆
  cases/<case_id>/
    manifest.json                # 原路径、相对归档路径、大小和SHA-256
    projects/houdini/            # 原始HIP/HIPLC/HIPNC
    projects/nuke/               # 原始NK
    dependencies/               # snapshot.json、patterns.json及必要资源
    previews/                    # 显式选择的预览
  modules/global/<software>/     # 验证后提炼的模块知识，沿用原机制
  imports/<import_id>/           # 合并来源快照和冲突证据
```

工程事实可立即检索；模型对原理的解释通过 `fx_learn_template_experience` 保存为 inferred/candidate，不默认作为成功方法召回。实际使用、用户纠错和确认仍通过原有 `fx_record_feedback → fx_finalize_learning → Dream/模块MD`，来源引用 study_id 和节点证据。不能因工程归档或索引成功就把推断升级为已验证经验。

同来源文件变化建立新修订，保留父修订和旧证据。默认来源ID包含项目、镜头、来源目录及相对文件名，避免同名文件串线；显式 template_key 可在同项目/镜头下跟随搬迁。默认搜索当前修订，include_history=true 搜索历史；合并分支都保留，等价内容折叠显示并可通过 history 展开全部来源。

## 迁移和多设备合并

停止源数据写入后，使用原有迁移工具复制到不存在的新目录：

```powershell
.venv\Scripts\python.exe scripts/migrate_data.py "D:/设备A/fx-agent/data" "E:/设备B/fx-agent/data"
```

已有数据的设备使用 `fx_import_data(source=...)` 预览，再 `apply=true` 追加合并；不要覆盖目标 SQLite。新表随原有数据一起合并，案例随相对路径复制和校验，旧数据库自动升级。原电脑路径只作来源记录；原路径不存在仍能读取归档、搜索并导出。

相同批次重复合并幂等；独立修订分支同时保留。同一study_id记录分歧时保留本机版本及导入快照，用 `fx_get_import_records(table="template_studies")` 展开双方，不按时间强行覆盖。经验冲突继续按既有记忆合并流程处理。
