# Windows 一键安装

安装的是 Houdini/Nuke 桥接插件、Python 依赖和当前 Codex 用户的全局 MCP/工作流，不安装 Houdini、Nuke 或 Codex 主程序，也不配置其他宿主。

## 双击安装

1. 把整个工程放在准备长期使用的位置，不能只复制 BAT 文件。
2. 预先安装 Houdini、Nuke15.2+，并至少启动 Houdini 一次以生成用户偏好目录。保存工程后关闭对应软件/桥接，停止正在写入记忆或归档的任务。
3. 双击工程根目录 **`Install-FX-Agent.bat`**，等待显示“安装配置完成”。出错时窗口会保留，后续步骤停止。
4. 重新启动 Houdini、Nuke，再重启 Codex 或新建聊天以刷新 MCP 工具与技能。

默认 Houdini18186、Nuke8187，不使用原版常见的8100/54321。端口占用时会停止，不自动关闭程序或改端口。两个客户端连接使用 stdio，以上是软件桥接端口。

脚本从自己的位置定位工程，运行目录不影响安装。自动选择已有的最高版本 Houdini 偏好目录，以及 Program Files 中最高版本的 Nuke15.2+；多个版本并存或非标准目录时应先预览并明确传入路径。当前真正做过只读连接验证的 Nuke 版本为15.2v1，不代表所有未来版本均已实测。

## PowerShell 与 BAT 命令

在工程目录运行 BAT，效果与双击相同：

```bat
Install-FX-Agent.bat
```

先预览路径和参数，不下载、不写配置：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\Install-FXAgent.ps1 -Plan
```

直接执行 PowerShell 安装：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\Install-FXAgent.ps1
```

明确软件位置或自选空闲端口：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\Install-FXAgent.ps1 `
  -HoudiniPrefDir "D:\Documents\houdini22.0" `
  -NukeExe "D:\Apps\Nuke15.2v1\Nuke15.2.exe" `
  -HoudiniPort 18186 -NukePort 18187
```

只安装 Houdini，或仅更新已有共享 Agent 的 Nuke 入口：

```bat
Install-FX-Agent.bat -Components Houdini
Install-FX-Agent.bat -Components Nuke
```

首次完整安装用默认 Both。仅 Nuke 模式要求当前工程的共享 `fx-agent` 入口已安装且指向工程 data，否则提示先运行 Both/Houdini；这样不会安装出一套缺少共享记忆的独立工具。单组件模式不主动卸载环境里已存在的另一组件依赖。

`-ExecutionPolicy Bypass` 仅用于本次 PowerShell 进程运行当前本地脚本，不调用 `Set-ExecutionPolicy`，不改系统持久策略。域策略仍可能禁止执行。BAT 最后会暂停显示结果；无人值守任务请直接运行 PowerShell，它会用非零退出码报告失败。

## 自动完成的步骤

- 检查工程、软件路径、端口及组件组合；预览模式在任何安装或配置修改之前返回。
- 缺少 Git/uv 时，按 [Git 官方说明](https://git-scm.com/install/windows) 和 [uv 官方说明](https://docs.astral.sh/uv/getting-started/installation/) 使用 WinGet 安装 `Git.Git` / `astral-sh.uv`。已有工具复用；没有 WinGet 时明确停止，需先手动安装依赖。系统安装提示由用户正常处理，脚本不执行网上下载的 PowerShell 代码。
- 用 uv 按锁文件同步当前工程 `.venv`，选用 Python3.12（必要时由 uv 下载），完整安装包含 nuke 组。不修改 Git 用户身份、远端、提交记录或进行推送。
- 先检查 Houdini 配置、准备并校验固定版本 Nuke 桥接，再依次调用现有 Python 安装器。软件主程序不会被启动或关闭。
- 数据固定在工程 `data/`。已存在的数据不清空、不合并；新目录不存在且检测到旧 `~/.fx-agent/memory.sqlite3` 时，使用现有校验迁移工具复制，保留原目录。检测到目标有文件却缺数据库时停止，避免忽略旧记忆。
- 原客户端和启动配置由各安装器备份到 `~/.fx-agent-install-backups/`。单个安装器支持失败回退；整个多阶段流程不是一个总事务，后一步失败不会撤销已成功的前置步骤。排除问题后可重新运行。

Houdini 偏好目录以真实 `hou.getenv("HOUDINI_USER_PREF_DIR")` 为准。环境变量已明确指定有效目录时优先使用；自动查找未发现目录时不会猜测创建版本目录，先启动 Houdini 或传入实际已有目录。

## 验证与迁移

安装完成表示配置已写入，不代表正在制作的画面已经验收。启动软件后，在普通用户终端执行：

```powershell
.venv\Scripts\python.exe scripts/check_houdini.py
.venv\Scripts\python.exe scripts/check_nuke.py
```

如使用自定义端口，Houdini 检查前设置 `$env:HOUDINI_PORT`，Nuke 检查传入 `--port`。完整回退见 [全局安装与首次连接](全局安装与首次连接.md) 和 [Nuke接入与独立学习](Nuke接入与独立学习.md)。

换设备可复制工程和 `data/` 后重新双击安装，保留案例、记忆、规范和工作流；复制前停止写入。不要复用旧电脑的 `.venv`，新设备需要重建环境，外部未归档素材与工程内部绝对路径仍需核对。安装成功也不代表客户端会自动恢复之前的聊天。
