# 全局经验、Dream 与跨设备追加导入

经验按软件、模块和适用条件全局召回。project_id 保留为来源及当前任务上下文，不再是经验检索的默认边界。工程进度、镜头路径、反馈轨迹仍使用项目与镜头定位；案例也保留原项目用于证据校验。

## 数据与旧版本兼容

- 数据库 schema 5 增加派生来源绑定、导入批次和冲突记录。打开旧库时事务升级，不重写旧经验文本、ID 或证据状态。
- 新 Experience 默认 reuse_scope=global；不提供 project_id 时使用 __global__。旧 payload 没有 reuse_scope 时，shot_id 非空的记录继续限定原项目/镜头，其他记录全局共享。需要推广工程特例时，基于证据另行提炼。
- fx_finalize_learning 默认 global，旧 project 值兼容为 global；shot 仍是明确限定。
- fx_search_memory 的 project_id 是上下文；source_project 才是可选的来源筛选。fx_get_memory 可跨项目展开，返回原项目、案例、来源和争议信息。
- 用户规范默认 global，明确限定时使用 project。规范保留用户原话；知识整理不改写用户规范。
- 全局模块文件位于 data/modules/global/<software>/<module>.md；旧项目目录及手写区不删除、不自动推广。新文件的自动区块由数据库重建，手写区保留。

## 由宿主助手执行 Dream

preview 返回全局候选摘要、next_cursor、truncated、snapshot 和精确别名建议。支持 software/module 筛选，分页无500条停用限制。相关完整记录通过 fx_get_memory 展开。检索本身保持字面关键词匹配；语义理解与整理由当前宿主助手完成，不启动第二个模型或后台任务。

动作结构：

```json
{
  "operation": "merge",
  "source_ids": ["来源经验ID1", "来源经验ID2"],
  "title": "烟雾尺度检查",
  "method": "先统一场景单位，再检查体素尺寸与求解参数。",
  "reason": "参数效果依赖场景尺度。",
  "applies_when": "Houdini Pyro；结合当前版本与输入核对。",
  "rationale": "两条来源描述相同前置检查，保留双方证据。",
  "modules": ["pyro"]
}
```

支持 merge/refine/split/conflict/supersede。拆分用多个动作引用同一来源；不同有效方法保持独立；冲突动作形成 disputed 记录，原方法的召回卡标记 has_conflict，展开可读 conflict_memory_ids。助手在使用前必须核查争议，不能把冲突说明当成成功方法。

语义整理只接受有效、全局可复用的活动来源，不混合软件，不把候选提升为成功。生成记录标记 host_synthesis_from_sources，不宣称新的视觉验证。原始经验不删除；新知识绑定完整来源及当时 payload。来源被纠正、停用、导入产生分歧，或 accepted 反馈不再是最新有效版本时，相关派生方法停止默认召回。

apply 要求当前 snapshot，最多20个语义动作。省略 actions 时应用精确别名，需重复 preview 的筛选与分页参数；actions=[] 表示不提交语义变更。新来源可与先前页面的完全重复经验比较。精确别名不会把派生方法指回被其覆盖的祖先。

fx_get_dream_runs 可查看已提交进度、展开动作与来源。next_cursor 是扫描位置，助手仍需在当前批次外主动搜索相关旧方法；它不代表所有内容已经语义审核。旧记录被修改后需要重新检查对应条目，不能仅依赖新行游标。

fx_undo_dream(run_id) 撤销该次创建的派生记录或别名，保留无关新增经验。相关来源或后续派生已变化时拒绝覆盖，需重新整理。reset 仅重置全局精确别名。

## 导入步骤

先停止源数据归档写入。数据库快照使用 SQLite 备份接口；文件逐个复制并校验；工程文件、预览和 manifest 引用均校验。导入前本机数据库备份保存在本批快照内。

```powershell
# 预览，不创建或升级目标数据库
.venv\Scripts\python.exe scripts/import_data.py "D:/FX-Import/device-B/data" "D:/MyScripts/fx-agent/data"
# 追加导入
.venv\Scripts\python.exe scripts/import_data.py "D:/FX-Import/device-B/data" "D:/MyScripts/fx-agent/data" --apply
```

MCP 入口为 fx_import_data(source, apply=false/true)，目标自动使用当前 FX_AGENT_DATA_ROOT。报告包含各表新增、跳过、冲突数量，新增经验ID和 Dream 待整理提示。

- ID与内容完全相同：跳过。
- 同一ID内容不同或唯一约束冲突：保留本机记录，把双方完整内容列入批次；同ID冲突经验暂停默认召回。
- 不同ID的相似方法：追加后交给 Dream 理解和整理。
- 反馈尝试只有存在相同来源且没有分叉修订时才接续。独立设备碰巧同名或出现不同分支，保留为冲突，不拼接成一条修订历史。
- 检查点冲突不按设备时间覆盖；先核对工程路径与实际状态。这里尚未引入可选择的独立 workspace_id，同名状态冲突采用保守保留策略。
- 案例ID相同、清单不同：保留当前案例与来源快照，依赖该冲突的记录不直接接入。
- 精确别名和生成文档不直接采用外部索引；从本机有效知识重建。手写材料保存在来源快照中供核查。

快照位于 data/imports/<内容指纹>/。指纹覆盖保留的表和文件；发布前完整复制，失败不发布半成品。重复导入会复核既有快照。imports 历史不再次打包，避免往返导入递归膨胀；当前表和文件仍完整保存。

## 分歧处理与恢复

fx_get_import_records() 列出批次；传 import_id、table、offset、limit 展开完整 incoming/local 内容。

经验分歧使用 fx_resolve_import_memory(import_id,memory_id,decision,expected_snapshot,rationale)。decision 为 keep_local/keep_incoming/keep_both。选择外部版本会建立独立分支ID并保留原文，选择 incoming 会停用原代表；保留两份后可继续 Dream。工具核对当前快照、原本地内容、案例及反馈来源，不允许强行绕过证据分歧。已解决决定在重复导入时保留。

从带未解决冲突的设备继续导出时，副本中的相应经验冻结为 needs_review，报告 upstream_needs_review 数量，避免第三台设备将它重新激活。空库首次收到这类记录时，当前没有单独的强制激活入口；应在源设备解决冲突，再重新导入并选择核实后的版本。

用户规范通过版本化规则接口保存最终决定和真实原话；检查点通过 expected_revision 保存核实后的新状态。案例、反馈链存在分歧时仍需助手逐项核对，当前不提供一键强制覆盖或自动重定位工程引用。

数据库事务与文件复制不是跨介质总事务。数据库失败时已完整发布的案例可能暂时无记录引用，原始数据和批次快照仍保留，重试可复用；不会删除来源。需要整体恢复时停止相关客户端，用批次中的 local-before.sqlite3 或执行前整库备份恢复；恢复前先保留之后新增的数据。
