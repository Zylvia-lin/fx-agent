# 模块工作流与学习同步

原模块准则是制作基线，记忆是带来源的历史经验；它们不混为一种数据。本轮核对旧 `fxhoudinimcp==2.25.0` 与当前固定依赖：36份Markdown无缺失、规范化换行后内容一致，31份模块工作流指南均保留。`get_workflow_guide` 继续直接读取依赖中的原指南。

## 模块分类

经验和纠错新增 `modules`，最多4个标签；`kind` 仍表示工作流、渲染或故障排查等经验类型，`effect_type` 仍表示具体效果。项目、镜头、软件与功能模块是不同维度。

常用 Houdini 标签为 sop、particles、pyro、flip、rbd、vellum、mpm、ocean、terrain、materials、lighting、rendering、solaris、cops、pdg、hda。完整标签与原指南主题映射通过 `fx_get_module_catalog(software="houdini")` 获取。POP、smoke、fluid、destruction等常用别名会规范化。Nuke有独立的合成、抠像、色彩等标签，不接受pyro等其他软件专属模块。

`fx_search_memory`、`fx_get_learning_history` 增加可选 `module` 过滤。空关键词配合模块可获取该模块少量经验；没有模块也没有关键词时仍不返回整库。默认条数与字符预算保持不变，卡片带模块字段。

旧记录读取时补默认 unclassified，不重写原payload、不猜测分类；默认内容hash保持兼容。纠正历史条目可以明确更正模块，但需保留原范围、来源和版本规则。Dream按软件与模块分组，不把不同模块的相同文字合并。

## 更新对应模块 MD

`fx_finalize_learning` 仍要求当前反馈已accepted、对应软件工程与预览已归档。提炼的方法、原因、适用条件连同反馈modules进入最终经验。随后根据SQLite中有效的learning_results，自动更新：

```text
data/modules/global/<software>/<module>.md
```

模块目录固定按软件与模块组织，项目名保留在数据库来源记录中。每份文档引用原模块指南，再附全局的已接受总结，不拼接聊天历史。完全相同的标题、方法、原因和条件仅显示一个方法区块，保留所有来源经验、反馈与案例ID。

只生成全局范围可复用的已提炼方法。候选、仅入库但未完成最终提炼、未分类和shot限定经验不推广为项目模块准则；仍可通过原经验工具查询。来源归档在提炼时验证，后续复用前须重新核验，不宣称视觉/因果全部已被程序证明。

反馈修订使旧方法失效、或显式纠正已提炼条目时，同步刷新模块MD，避免继续加载旧方案。上游原MD保持不变，防止uv重装/升级丢失学习成果；实际制作会先读原指南，再读当前项目的模块补充。

## 手写内容、并发与失败

- 只替换 `FX MODULE LEARNING START/END` 自动区块，手写补充应放区块外。手写备注是资料，不是自动验证过的成功经验，也不能提供新的操作授权。
- 管理标记丢失、重复或顺序损坏时停止更新并保留原文件；不静默覆盖。源经验文本中的同名标记会转义。
- 数据库仍是事实源。派生文档更新持有SQLite写事务，串行化多个客户端的快照；文件使用同目录临时文件与原子替换，防止半个MD。
- DB提交与多份MD发布不是跨介质总事务。写入失败会保留已提交经验，返回 `module_guides.state=pending_rebuild` 与错误。部分文件可能已更新，使用 `fx_refresh_module_guides(project_id)` 重建；不要伪称经验回滚或重复追加反馈。
- `fx_get_module_knowledge(project_id,module,software,max_chars)` 读取前核对数据库变更标记与文档SHA-256；未变化时复用，变化后只刷新所选模块。文件被删除或手工修改时也会重新核对；同步失败会报错，不把旧文本假装成最新内容返回。默认4000、最多12000 JSON字符；需要具体方法时按ID展开原经验，而不是加载所有模块历史。
- Dream提炼结果只覆盖其实际标签。比如原经验为 `sop + ocean`，提炼结果仅为 `ocean` 时，`sop` 检索和文档仍保留原经验。
- 存在有效争议记录的方法，在文档标题后显示“存在争议”及记录ID。返回结构中的 `has_conflict`、`conflict_memory_ids`（最多3条）和 `omitted_conflicts` 独立于正文截断；先展开冲突再决定是否复用。撤销争议后重新同步会移除提示。

标签与文档按软件与模块全局共享，具体方法按适用条件复用。当前用户指令与制作规范优先于历史经验。原指南首次进入模块时读取，后续按需或连续失败时重读，不每个工具调用都全文注入。

## 激活与验证边界

当前制作对话可以继续，不中断Houdini。完成阶段后重启Codex加载新MCP工具/参数，`fx_status.module_taxonomy_version=1` 表示新版已加载。新增 `fx_get_module_catalog`、`fx_get_module_knowledge`、`fx_refresh_module_guides`，当前FX入口工具数量为246；Nuke操作入口仍25项。

仅现有已确认经验会触发真实模块MD生成。正在修改或尚未认可的海浪参考与问题不能作为成功案例，本轮没有接管、修改或验收实际海浪工程。

跨设备追加导入、全局 Dream 与迁移规则见[全局经验与数据合并](全局经验与数据合并.md)。
