# Windows Codex 全局安装与首次连接

FX Agent 不再要求以 Codex 插件安装。宿主助手负责判断与操作，当前工程提供 stdio MCP、制作工作流和持久数据。当前已实现 Windows Codex 全局安装；Claude、DeepSeek Harness、WorkBuddy 的安装适配尚待分别验证。

## 首次安装

需要安装 Houdini、Python 3.12+、Git 与 uv。先安装 Codex 并完成正常登录。MCP 服务本身不需要独立模型 API Key。

```powershell
git clone https://github.com/Zylvia-lin/fx-agent.git D:\MyScripts\fx-agent
Set-Location D:\MyScripts\fx-agent
uv sync --frozen
.venv\Scripts\python.exe scripts/install_codex.py --houdini-pref "$HOME/Documents/houdini22.0"
```

已有当前工程时直接进入该目录，不要再次 clone。`--houdini-pref` 必须是实际 Houdini 偏好目录，版本或 Documents 重定向不同时相应修改；可在 Houdini Python Shell 查询 `hou.getenv("HOUDINI_USER_PREF_DIR")`。不带 `--apply` 只预览，确认路径后执行：

```powershell
.venv\Scripts\python.exe scripts/install_codex.py --houdini-pref "$HOME/Documents/houdini22.0" --port 18186 --data-root "D:/MyScripts/fx-agent/data" --apply
```

安装内容：

- Codex 用户配置 `~/.codex/config.toml`：注册 `fx-agent`，执行当前工程 `.venv/Scripts/python.exe -m fx_agent`，移除旧 `fxhoudini` 表。
- Houdini `packages/fx-agent.json`：加载当前工程依赖内的桥接组件，监听 `127.0.0.1:18186`，移除旧 `packages/fxhoudinimcp.json`。上游代码作为受锁文件约束的依赖继续复用，不再加载旧目录版本。
- 用户 `~/.agents/skills/fx-workflow`、`fx-learning`、`nuke-workflow`、`fx-project-learn`：创建指向当前仓库工作流的目录联接，代码更新后工作流同步更新。已有同名其他内容时拒绝覆盖。
- 将记忆位置明确固定为当前工程的 `data/`，保留已有数据库和案例。安装器不清空或自动迁移生产记忆。旧版用户先按下述迁移命令复制数据，再更新注册。

原客户端配置与启动包备份到 `~/.fx-agent-install-backups/<时间>/`，其中可能包含私密配置，不要提交或分享。安装步骤失败会尝试恢复原文件。请勿在安装期间由其他进程编辑这些配置。遇到不支持的 TOML 写法会停止，避免误删其他服务。

升级优先读取已有新启动包，否则读取旧包，保留已有超时、工程根目录限制与额外环境变量；明确更新桥接路径、端口、本机监听、自动启动与关闭自动排版。不能安全迁移的包格式会停止安装。若某项回退也失败，会继续恢复其他文件、清理已创建联接，并报告备份和失败路径。

端口 18186 是 Houdini 桥接端口。客户端 MCP 使用 stdio，不能将 `http://127.0.0.1:18186` 直接当成 HTTP MCP URL。安装器将单次工具超时配置为 3600 秒；超过一小时的制作任务需按实际工作调整 Codex 的 `tool_timeout_sec`。

## 激活与验证

1. 保存正在制作的工程，再正常重启 Houdini，使新启动包与端口生效。安装器不关闭 Houdini，不保存或替换当前工程。
2. 重启 Codex 或新建聊天，避免沿用旧 MCP 工具清单。
3. 在仓库目录运行只读检查：

```powershell
.venv\Scripts\python.exe scripts/check_houdini.py
```

检查会创建独立 MCP 客户端、握手、列工具、查询数据目录、连接与场景。应看到 241 个工具、`connected: true`，并核对目标 Houdini 工程。它不创建节点，也不证明实际效果制作成功。连接失败时先检查 Houdini 启动日志、18186 端口占用、Houdini 偏好目录和包文件，不要同时恢复两套入口试错。

Houdini 尚未启动时，可运行 `.venv\Scripts\python.exe scripts/check_houdini.py --mcp-only` 仅检查 MCP 注册能力与规范读取。该模式不证明 Houdini 可连接。受限沙箱内访问用户数据库可能报只读；应在正常用户终端验证，不要因此删除数据库或放宽目录的公开权限。

在新聊天要求助手先读取 `fx-workflow`、调用 `fx_status` 与 `fx_get_production_rules`；确认返回同一数据根目录和已有规范。当前聊天可继续持有旧连接，新配置落盘不代表聊天工具立即刷新。

## 升级、卸载和回退

升级时在工程目录 `git pull`、`uv sync --frozen`，再预览并应用安装器。移动工程路径或更换 Python 环境后也需重新安装；目录联接指向不同路径时先人工核对旧链接。

卸载：用 `codex mcp remove fx-agent` 移除注册；删除 Houdini 的 `packages/fx-agent.json`；仅移除上述四个技能的目录联接本身，不能递归删除联接目标。记忆目录与仓库由用户保留，卸载不自动删除。

回退：退出客户端后，根据备份 `manifest.json` 恢复原 `config.toml` 和旧 `fxhoudinimcp.json`，移除新增启动包与技能联接，再重启 Houdini 与客户端。完整配置恢复前应比较安装之后的新修改，以免覆盖其他工具配置。旧虚拟环境保留用于回退，无需下载旧代码。

## 多宿主与迁移边界

后续其他宿主应注册同一仓库入口，显式配置同一个绝对 `FX_AGENT_DATA_ROOT`，以共享同一份规范、记忆与案例，而不是为每个客户端复制数据库。SQLite 提供事务与修订检查，但并行操作同一 Houdini 工程仍需由操作者协调。

换电脑时需重新创建 Python 环境与宿主注册，不能复制 Windows `.venv` 代替安装。停止所有写入进程后再整体备份数据目录，保留数据库、案例与文件清单；可同时存在的 SQLite WAL 文件也不能遗漏。当前提供经校验的追加导入，见[全局经验与数据合并](全局经验与数据合并.md)；历史源路径、检查点、HIP 内外部引用不会自动适配新电脑，不能把文件拷贝成功视为工程已可复现。可迁移包与路径检查属于后续实现。

Codex 配置字段和技能目录依据官方 [MCP 文档](https://learn.chatgpt.com/docs/extend/mcp?surface=cli) 与 [Skills 文档](https://learn.chatgpt.com/docs/build-skills)。

## 从旧用户目录迁到当前工程

停止会写入记忆或归档的客户端后，在工程目录执行：

```powershell
.venv\Scripts\python.exe scripts/migrate_data.py "$HOME/.fx-agent" "D:/MyScripts/fx-agent/data"
.venv\Scripts\python.exe scripts/install_codex.py --houdini-pref "$HOME/Documents/houdini22.0" --apply
```

迁移使用 SQLite 备份接口创建一致数据库副本，逐文件校验，并校验已有案例清单；目标已存在时拒绝合并，原目录完整保留供回退。目录联接、符号链接或损坏案例会使迁移停止。迁移期间必须停止归档文件写入；数据库事务锁不能锁住外部文件系统操作。

此后将整个工程目录连同 `data/` 复制到新设备即可带走已存规范、记忆、反馈、案例副本和仓库工作流。运行数据不推送 Git。新设备仍需安装软件和依赖、重新运行安装器生成新机器路径；运行中的数据库、未归档外部素材、HIP/NK 内绝对引用不属于自动可迁移保证。不要直接复用旧 `.venv`。
