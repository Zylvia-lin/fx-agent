# 参考工程只读剖析与纯文本经验提炼

本技能用于用户明确提供参考工程希望“搞懂核心原理并沉淀成通用经验”的场景。

> **严格边界**：
> - **源工程只读**：绝不修改、覆盖或重存用户源工程；打开 Houdini 参考工程先切 `Manual` 更新模式避免无关 cook。
> - **不存任何项目文件**：不归档 `.hip` / `.nk` / `.ma`，不收集贴图，不保存截图/序列，不生成重型效果卡。若工程资产本身值得原样复用，由用户将其收入外部 **FX Template 特效模板库**，日常通过 `fx_search_published_templates` 直接检索。

## 执行步骤

1. **明确剖析目标**：与用户确认要看懂哪个具体效果或工艺（例如某种程序化光丝、边缘光材质、分阶段缓存结构、合成发光组合），不盲目全工程地毯式扫描。
2. **只读检查真实网络**：
   - 在 DCC 会话中只读追踪与目标效果直接相关的上下游节点、核心 VEX/表达式、关键属性流转、材质连接与渲染/合成设置。
   - 遇到未连接、旁路或残留的旧分支，如实区分，不把死分支写成生效方法。
3. **脱敏提炼纯文本通用经验**：
   - 剥离项目名、镜头号、本机盘符绝对路径、角色专属节点名和单镜头写死数值。
   - 将可跨项目迁移的**核心思路 + 节点骨架 + 可控设计 + 适用边界与注意事项**整理为精炼纯文本（150–600 字）。
4. **写入纯文本知识库**：
   - 经用户确认或现场核实后，调用 `fx_submit_experience`（`project_dependent=False`、`project_id="__global__"`、`case_id=""`、`reuse_scope="global"`、明确 `software` 和 `modules`）写入纯文本经验；自动刷新 `data/modules/global/<software>/<module>.md`。
   - 若仅属结构静态观察、尚未实际运行验证，如实说明验证边界，不夸大为已视觉验收方案。
